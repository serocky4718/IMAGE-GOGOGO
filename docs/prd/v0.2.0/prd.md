## 版本概述

本版本目标是在 v0.1.0 已完成本地生图闭环的基础上，升级为更适合长期创作的图片工作室：支持提示词保存与读取、每个对话独立配置、自动识别文生图/图生图、优化参数选择方式，并将界面改为更简洁干净的生产力工具风格。

### 成功指标

- 用户可以保存常用提示词，并在后续对话中读取复用。
- 每个对话的提示词、参考图和生成参数互不串联。
- 用户无需手动选择文生图或图生图，系统根据是否存在参考图自动判断。
- 生成图和生成记录图片可以放大、缩小和拖拽查看。
- 主界面更简洁，应用名称统一为“Rocky的图片工作室”。

### 需求总览

| 需求 | 描述 | 优先级 | 相关文档 |
|------|------|--------|----------|
| 提示词保存与读取 | 保存常用提示词，支持缩略图和读取复用 | P0 | 本文档 / design.md / dev.md |

| 界面简洁化与品牌调整 | 改为类似 Codex / Claude Code 的清爽工具界面 | P1 | design.md |

## 需求 1：提示词保存与读取

### 1.1 背景与目标

**当前问题**：  
用户需要反复输入常用提示词，且无法把效果好的提示词作为素材保存。对于新手或高频创作者来说，这会增加重复劳动和试错成本。

**目标**：
- 用户可以保存当前提示词。
- 用户可以为保存的提示词添加缩略图。
- 用户可以从提示词库读取提示词到当前对话。
- 提示词库不影响历史生成记录。

### 1.2 用户故事

- 作为用户，我希望保存常用提示词，以便下次不用重新输入。
- 作为用户，我希望提示词可以带缩略图，以便快速识别它适合生成什么效果。
- 作为用户，我希望读取提示词时只影响当前对话，以便不会误改其他对话内容。

### 1.3 需求详情

**功能要求**：
1. 输入区需要提供“保存提示词”和“读取提示词”入口。
2. 保存提示词时至少保存标题、完整提示词、创建时间和更新时间。
3. 保存提示词时可以记录一张缩略图，缩略图可来自当前参考图或当前选中的生成图。
4. 读取提示词后，将提示词填入当前对话输入框。
5. 提示词库需要持久化到本地状态。
6. 提示词库为空时，应展示明确空状态。
7. 缩略图缺失时，展示占位样式，不应报错或显示破损图片。

### 1.4 验收标准

- [ ] 用户可以把当前输入框内容保存为提示词。
- [ ] 保存后的提示词可以在提示词库中看到标题、摘要和缩略图。
- [ ] 用户可以点击提示词，将内容读取到当前对话。
- [ ] 读取提示词不会改变其他对话的输入内容。
- [ ] 应用重启后，已保存提示词仍存在。
- [ ] 没有缩略图的提示词不会造成界面破损。

## 需求 2：每个对话独立设置

### 2.1 背景与目标

**当前问题**：  
当前无论新增多少个对话，提示词和参数仍共用一套状态，容易导致用户在 A 对话中的创作内容影响 B 对话。

**目标**：
- 每个对话保存自己的提示词。
- 每个对话保存自己的参考图。
- 每个对话保存自己的比例、分辨率和 quality。
- 切换对话时恢复对应对话的状态。

### 2.2 用户故事

- 作为用户，我希望每个对话保存自己的提示词，以便同时推进多个创作方向。
- 作为用户，我希望每个对话拥有自己的参数，以便横图、竖图、高清图等任务互不干扰。
- 作为用户，我希望重启应用后继续之前的对话状态，以便不中断工作流。

### 2.3 需求详情

**功能要求**：
1. 对话对象需要包含独立的输入区状态。
2. 对话状态至少包含：提示词、参考图、比例、分辨率、quality。
3. 新建对话时使用默认参数，不复制其他对话的提示词。
4. 切换对话时，输入区应恢复当前对话保存的状态。
5. 旧版本没有独立输入区状态的数据需要自动补默认值。

### 2.4 验收标准

- [ ] 对话 A 输入提示词后，切换到对话 B，B 不显示 A 的提示词。
- [ ] 对话 A 和 B 可以分别选择不同的比例、分辨率和 quality。
- [ ] 对话 A 添加参考图后，切换到 B 不显示 A 的参考图。
- [ ] 重启应用后，每个对话的提示词和参数仍能恢复。
- [ ] 旧版本数据可以正常打开，不出现白屏或状态读取失败。

## 需求 3：自动生成模式判断

### 3.1 背景与目标

**当前问题**：  
用户需要手动选择文生图或图生图，但实际判断逻辑很简单：没有输入图片就是文生图，有输入图片就是图生图。手动模式会增加认知负担，也容易选错。

**目标**：
- 移除手动“文生图 / 图生图”模式选择。
- 没有参考图时自动文生图。
- 有参考图时自动图生图。
- 界面以状态文本说明当前自动识别结果。

### 3.2 用户故事

- 作为用户，我希望上传参考图后自动进入图生图，以便不用额外理解模式概念。
- 作为用户，我希望移除参考图后自动回到文生图，以便操作更自然。

### 3.3 需求详情

**功能要求**：
1. 输入区不再显示模式切换控件。
2. 参考图为空时，请求参数使用 `text-to-image`。
3. 参考图存在时，请求参数使用 `image-to-image`。
4. 当前自动识别模式可以用轻量文本展示。
5. 能力边界提示需要根据自动模式计算。

### 3.4 验收标准

- [ ] 界面不再出现“文生图 / 图生图”手动切换按钮。
- [ ] 未添加参考图时提交生成，请求按文生图处理。
- [ ] 添加参考图后提交生成，请求按图生图处理。
- [ ] 移除参考图后再次提交，自动恢复文生图。

## 需求 4：参数控件简化

### 4.1 背景与目标

**当前问题**：  
比例、分辨率、quality 当前以按钮组形式铺开，占用空间较多。后续比例选项增加后，界面会更拥挤。

**目标**：
- 将比例、分辨率、quality 改为紧凑选择器。
- 增加更多常用比例。
- 保持当前值一眼可见。

### 4.2 用户故事

- 作为用户，我希望快速看到当前分辨率是 1K、2K 还是 4K，以便确认生成成本和清晰度。
- 作为用户，我希望点击后再展开选项，以便界面更干净。
- 作为用户，我希望有更多横竖比例，以便适配不同图片用途。

### 4.3 需求详情

**功能要求**：
1. 分辨率显示为类似“分辨率 1K”的紧凑控件。
2. 点击后可选择 1K、2K、4K。
3. 比例和 quality 使用同类交互。
4. 比例增加 `3:2`、`2:3`、`2:1`。
5. 参数选择变化后保存到当前对话状态。

### 4.4 验收标准

- [ ] 比例可选项包含 `1:1`、`4:3`、`3:4`、`16:9`、`9:16`、`3:2`、`2:3`、`2:1`。
- [ ] 分辨率可选项包含 `1K`、`2K`、`4K`。
- [ ] quality 可选项包含 `low`、`medium`、`high`。
- [ ] 参数控件不会挤压提示词输入框。
- [ ] 参数变化会写入当前对话状态。

## 需求 5：图片缩放拖拽预览

### 5.1 背景与目标

**当前问题**：  
生成图片只能普通预览，无法放大查看细节，也无法移动图片查看局部。这会影响用户判断图片质量。

**目标**：
- 当前生成图可以缩放和拖拽。
- 生成记录里的图片也可以缩放和拖拽。
- 预览弹窗提供重置视图能力。

### 5.2 用户故事

- 作为用户，我希望放大图片查看局部细节，以便判断是否需要重新生成。
- 作为用户，我希望拖动放大后的图片，以便查看不同区域。
- 作为用户，我希望一键重置视图，以便回到完整预览状态。

### 5.3 需求详情

**功能要求**：
1. 图片预览弹窗支持放大、缩小。
2. 图片放大后支持鼠标拖拽移动。
3. 弹窗需要提供重置视图按钮。
4. 当前生图区和生成记录都复用该预览弹窗。
5. 关闭弹窗后再次打开，应恢复默认适配视图。

### 5.4 验收标准

- [ ] 点击当前生成图后，可以在弹窗中放大、缩小。
- [ ] 点击生成记录图片后，可以在弹窗中放大、缩小。
- [ ] 放大后可以拖拽移动图片。
- [ ] 点击重置后图片回到默认位置和缩放。
- [ ] 关闭再打开预览时，不沿用上一次拖拽位置。

## 需求 6：界面简洁化与品牌调整

### 6.1 背景与目标

**当前问题**：  
当前界面偏工作台首版风格，信息较多，部分底部信息与顶部信息重复。用户希望整体更像 Codex、Claude Code 这类简洁、干净、专注的工具界面。

**目标**：
- 应用名称改为“Rocky的图片工作室”。
- 删除标题处图标显示。
- 移除输入区底部重复的“当前API”和“参数边界：模式”。
- 顶部保留必要 API 和参数确认信息。
- 整体视觉更简洁、克制、清爽。

### 6.2 用户故事

- 作为用户，我希望界面更干净，以便长期使用不疲劳。
- 作为用户，我希望 API 和参数信息集中展示，以便生成前确认。
- 作为用户，我希望应用名称更符合个人工作室定位，以便使用起来更有归属感。

### 6.3 需求详情

**功能要求**：
1. 顶部品牌名称显示为“Rocky的图片工作室”。
2. 删除品牌区图标显示。
3. 打包产品名称同步调整。
4. 输入区不再重复显示“当前API”和“参数边界：模式”两个框。
5. API、模型和关键参数信息可以在顶部或更轻量的位置保留。
6. 样式减少厚重阴影和强装饰色，以中性色、细边框、留白为主。

### 6.4 验收标准

- [ ] 主界面标题显示“Rocky的图片工作室”。
- [ ] 标题旁不再显示原图标。
- [ ] 输入区底部不再出现重复 API 和参数边界框。
- [ ] 顶部仍可确认当前 API 和模型。
- [ ] Windows 打包产物名称同步更新。

## 非功能需求

### 兼容性要求

- 继续支持 Windows 10 本地桌面使用。
- 旧版本本地状态需要自动兼容迁移。

### 可用性要求

- 提示词保存、读取、生成操作不应互相干扰。
- 模式自动判断需要足够直观，用户不应困惑当前是文生图还是图生图。
- 图片缩放拖拽需要有明确的重置入口。

### 稳定性要求

- 本地状态读取失败时不得导致应用白屏。
- 缩略图数据缺失或图片加载失败时，界面需要展示占位状态。
- 图片预览交互不得影响生成记录保存。

---

## 约束与依赖

- 本版本不新增云端账号体系，提示词库仍保存在本地。
- 本版本不要求提示词分类、搜索、标签，可作为后续扩展。
- 本版本不改变第三方 API 协议适配范围。
- 本版本不要求拖拽上传图片到输入区，可作为后续体验优化。
