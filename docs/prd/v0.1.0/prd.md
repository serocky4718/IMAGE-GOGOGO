## 版本概述

本版本目标是交付一个可在 Windows 10 本地运行的桌面生图程序，用户可以配置第三方生图 API，在窗口中通过文生图或图生图方式生成图片，并查看生成图片与预览结果。

### 成功指标

- 用户可以在 Windows 10 上通过 EXE 文件启动程序。
- 用户可以配置多个第三方 API 供应商，并看到、切换当前使用的 API 与模型。
- 用户可以输入提示词发起生图请求，并在窗口内看到生成结果。
- 用户可以选择文生图或图生图，并设置画面比例、分辨率档位和质量档位。
- 程序具备标准 Windows 窗口能力，包括最小化、最大化和关闭。
- 主界面能够清晰呈现生成窗口列表、当前生图区、输入区和生成图片预览区。

### 首版范围原则

- v0.1.0 优先完成“配置 API → 设置参数 → 提交生成 → 查看结果 → 回看预览”的核心闭环。
- v0.1.0 不追求一次性覆盖所有第三方生图服务的完整能力，优先保证至少一种可配置 API 的稳定使用。
- API 能力识别、参数自动映射、批量队列、复杂历史管理等能力可以预留入口，但不作为首版发布阻断项。

## 需求 1：桌面程序启动与窗口能力

### 1.1 背景与目标

**当前问题**：  
用户需要一个本地运行的生图程序，而不是只能在浏览器或命令行中使用的工具。

**目标**：
- 程序可以在 Windows 10 平台启动和使用。
- 程序以 EXE 文件形式交付，便于普通用户打开。
- 程序拥有标准 Windows 应用窗口行为。

### 1.2 用户故事

- 作为 Windows 用户，我希望直接双击 EXE 启动程序，以便不需要额外理解开发环境。
- 作为 Windows 用户，我希望窗口支持最小化、最大化和关闭，以便符合日常桌面应用使用习惯。

### 1.3 需求详情

**功能要求**：
1. 程序需要支持 Windows 10 平台运行。
2. 程序需要能够以 EXE 文件形式交付。
3. 程序窗口需要支持最小化、最大化和关闭。
4. 程序启动后应直接进入主界面，不需要先进入营销页或说明页。

### 1.4 验收标准

- [ ] 在 Windows 10 环境下可以通过 EXE 文件启动程序。
- [ ] 启动后出现 Windows 程序窗口。
- [ ] 窗口最小化、最大化和关闭按钮可正常使用。
- [ ] 程序启动后展示主生图界面。

## 需求 2：第三方 API 供应商配置与边界提示

### 2.1 背景与目标

**当前问题**：  
不同用户可能同时使用多个第三方生图服务，程序需要允许用户配置多个 API 供应商，并在生成前切换当前供应商，而不是固定单一服务。同时，部分 API 服务商不会清晰说明所有参数能力边界，程序需要用可理解的方式提示用户，而不是假设所有参数都一定可用。

**目标**：
- 用户可以设置多个生图 API 供应商所需的基础信息。
- 用户可以知道当前请求将使用哪个 API 和哪个模型。
- 用户可以在多个已配置 API 供应商之间切换。
- 用户可以理解当前 API 的能力边界可能来自配置、默认假设或请求返回结果。
- 当 API 配置缺失或不可用时，用户能够得到明确反馈。

### 2.2 用户故事

- 作为用户，我希望可以设置第三方 API，以便使用我自己的生图服务账号。
- 作为用户，我希望可以添加多个 API 供应商，以便按场景使用不同服务。
- 作为用户，我希望可以切换当前 API 供应商，以便决定本次请求发送到哪个服务。
- 作为用户，我希望在输入区附近看到当前 API 和模型，以便确认本次生图请求的目标服务。
- 作为用户，我希望知道当前 API 对文生图、图生图、尺寸、分辨率和质量的支持情况是否明确，以便减少试错。
- 作为用户，我希望配置不完整时程序给出提示，以便我知道需要补充什么信息。

### 2.3 需求详情

**功能要求**：
1. 程序需要提供 API 设置入口。
2. 程序需要支持添加多个 API 供应商配置。
3. API 设置至少应覆盖服务名称、API 地址、认证信息和模型名称。
4. 程序需要在对话框区域显示当前使用的 API 和模型。
5. 程序需要允许用户在已配置 API 供应商之间切换。
6. 程序需要允许用户修改已配置的 API 信息。
7. API 设置需要允许用户记录该 API 是否支持文生图、图生图、尺寸比例、分辨率档位和质量档位。
8. 当 API 能力边界不明确时，程序需要允许用户按默认参数尝试请求，并在失败后展示可理解的失败原因。
9. `supported / unsupported / unknown` 在 v0.1.0 主要承担信息提示作用，不作为强制禁用或阻断规则。
10. 当没有可用 API 配置时，程序不应静默失败，应提示用户先完成配置。
11. 程序应将“API 配置方案”作为可复用概念，便于后续扩展不同服务商或 API 模板。

### 2.4 验收标准

- [ ] 用户可以打开 API 设置入口。
- [ ] 用户可以添加多个 API 供应商配置。
- [ ] 用户可以填写、保存和修改 API 配置信息。
- [ ] 用户可以在多个已配置 API 供应商之间切换当前 API。
- [ ] 主界面对话框区域可以看到当前使用的 API 名称和模型名称。
- [ ] 用户可以看到当前 API 对生图模式和常用参数的支持状态，或看到“未知/未确认”的状态。
- [ ] 未配置 API 时发起生图请求，程序会提示需要先配置 API。
- [ ] API 请求失败时，程序会展示可理解的失败状态。
- [ ] API 能力边界未知时，程序不会把所有参数支持情况展示为已确认。
- [ ] `supported / unsupported / unknown` 在首版以提示为主，不要求强制禁用模式或阻断生成。

## 需求 3：生图对话流程

### 3.1 背景与目标

**当前问题**：  
用户需要通过自然语言提示词与生图程序交互，并保留上下文记录便于回看。

**目标**：
- 用户可以在主界面输入提示词。
- 用户可以在生成前选择文生图或图生图。
- 程序可以将输入内容作为生图请求发出。
- 左侧区域显示不同生成窗口，方便用户在多个生成线程之间切换。

### 3.2 用户故事

- 作为用户，我希望在对话框中输入生图提示词，以便快速描述想要的图片。
- 作为用户，我希望可以选择文生图或图生图，以便根据创作场景使用纯文本或参考图片生成结果。
- 作为用户，我希望左侧可以新增和切换生成窗口，以便同时维护多个生成线程。
- 作为用户，我希望看到生图中的等待状态，以便知道程序正在处理请求。

### 3.3 需求详情

**功能要求**：
1. 主界面底部需要提供对话输入框。
2. 用户需要能够选择文生图或图生图模式。
3. 文生图模式下，用户输入提示词后可以提交生图请求。
4. 图生图模式下，用户需要能够选择或添加参考图片，并结合提示词提交生图请求。
5. 图生图模式下，用户需要能够看到当前参考图片缩略图，并可以移除参考图片。
6. 左侧生成窗口区域需要支持新增窗口、切换窗口，并展示每个窗口的最近生成状态。
7. 生图过程中需要有明确的进行中状态。
8. 生图完成或失败后，当前生成窗口需要反映对应结果。

### 3.4 验收标准

- [ ] 用户可以在对话框输入提示词。
- [ ] 用户可以在文生图和图生图之间切换。
- [ ] 图生图模式下，用户可以选择或添加参考图片。
- [ ] 图生图模式下，界面可以明确显示当前参考图片是否会参与本次生成。
- [ ] 用户可以移除当前参考图片。
- [ ] 用户可以提交提示词并触发生图请求。
- [ ] 左侧可以新增生成窗口，并在不同窗口之间切换。
- [ ] 生图过程中界面会展示进行中状态。
- [ ] 生图完成、失败或取消时，当前生成窗口会展示对应状态。

## 需求 4：生图模式与参数预设

### 4.1 背景与目标

**当前问题**：  
生图结果受模式、尺寸、清晰度和质量影响明显，用户需要在发起请求前快速选择常用预设，而不是每次手动输入复杂参数。

**目标**：
- 支持文生图和图生图两类常用生成模式。
- 支持常规画面比例预设，覆盖横图、竖图和方图场景。
- 支持 1K、2K、4K 分辨率档位。
- 支持 low、medium、high 质量档位。

### 4.2 用户故事

- 作为用户，我希望选择画面比例，以便生成适合不同用途的横图、竖图或方图。
- 作为用户，我希望选择 1K、2K 或 4K，以便在速度、成本和清晰度之间取舍。
- 作为用户，我希望选择 low、medium 或 high 质量，以便控制生成质量和消耗。
- 作为用户，我希望图生图时可以先预览参考图片，以便确认使用了正确图片。

### 4.3 需求详情

**功能要求**：
1. 程序需要提供生图模式选择，至少包含文生图和图生图。
2. 程序需要提供尺寸比例预设，至少包含 1:1、4:3、3:4、16:9、9:16。
3. 程序需要提供分辨率档位预设，至少包含 1K、2K、4K。
4. 程序需要提供质量档位预设，至少包含 low、medium、high。
5. 用户选择的模式、尺寸比例、分辨率和质量需要在提交前可见。
6. 如果某个 API 或模型明确不支持用户选择的参数，程序需要给出明确提示，但 v0.1.0 不要求强制禁用或阻断生成。
7. 图生图模式下，用户选择参考图片后需要显示参考图片预览。
8. 如果某个 API 或模型的参数支持情况未知，程序需要以“未知/未确认”状态呈现，避免误导用户。

### 4.4 验收标准

- [ ] 用户可以选择文生图模式。
- [ ] 用户可以选择图生图模式。
- [ ] 用户可以选择 1:1、4:3、3:4、16:9、9:16 等尺寸比例预设。
- [ ] 用户可以选择 1K、2K、4K 分辨率档位。
- [ ] 用户可以选择 low、medium、high 质量档位。
- [ ] 提交请求前，界面能显示当前选择的模式、比例、分辨率和质量。
- [ ] 图生图模式下，参考图片可在提交前预览。
- [ ] 参数不被当前 API 或模型支持时，程序会提示用户调整参数，但首版不要求强制拦截。
- [ ] 参数支持情况未知时，界面能提示用户该参数可能需要通过实际请求验证。

## 需求 5：生图结果展示与图片预览

### 5.1 背景与目标

**当前问题**：  
生成图片需要在主界面中被直观看到，同时用户还需要右侧预览区快速浏览生成结果。

**目标**：
- 中间区域展示当前主要生成图片。
- 右侧区域展示已生成图片预览，并作为生成记录入口。
- 用户可以通过预览区切换查看不同生成结果。
- 用户可以对当前图片进行预览查看，便于确认细节。

### 5.2 用户故事

- 作为用户，我希望在中间区域看到当前生成的大图，以便检查结果是否符合预期。
- 作为用户，我希望在右侧看到生成图片预览和基础生成信息，以便快速浏览多个结果。
- 作为用户，我希望点击预览图后能在主生图区查看对应图片，以便比较不同结果。
- 作为用户，我希望可以打开图片预览，以便查看图片细节。

### 5.3 需求详情

**功能要求**：
1. 中间上方区域需要作为主要生图区。
2. 右侧区域需要展示生成图片的预览列表或预览网格，并承担生成记录入口的角色。
3. 生图完成后，生成结果需要进入右侧预览区。
4. 当前选中的图片需要在中间生图区显示。
5. 用户需要能够从右侧预览区选择图片，并在中间生图区查看。
6. 程序需要提供图片预览能力，用于查看当前图片或预览区图片。
7. 图片预览需要能区分生成图和图生图参考图，避免用户误认。
8. 每条生成记录应至少包含缩略图、生成状态和生成时间。
9. 生成记录宜展示提示词摘要、模型、尺寸比例、分辨率和质量，便于用户回看。
10. 如果暂无生成图片，生图区和预览区应展示空状态。

### 5.4 验收标准

- [ ] 生图完成后，中间生图区显示生成结果。
- [ ] 生图完成后，右侧预览区出现对应图片预览。
- [ ] 点击右侧预览图后，中间生图区切换为对应图片。
- [ ] 用户可以打开图片预览查看当前图片。
- [ ] 右侧预览区能展示生成状态和生成时间。
- [ ] 图生图参考图片可以在提交前预览。
- [ ] 无图片时，生图区和预览区不会显示错误或空白崩坏状态。

## 需求 6：三栏五等份界面布局

### 6.1 背景与目标

**当前问题**：  
主界面需要同时承载生成窗口选择、主要生图、输入对话和图片预览，布局需要清晰稳定。

**目标**：
- 主界面从左到右按 5 份切分。
- 左侧生成窗口选择占 1 份。
- 中间工作区占 2 份。
- 右侧生成图片预览占 2 份。

### 6.2 用户故事

- 作为用户，我希望生成窗口、生图区和预览区分区明确，以便快速找到当前任务信息。
- 作为用户，我希望中间区域同时包含生图区和对话框，以便边看图边继续输入。
- 作为用户，我希望生成参数和当前 API/模型信息靠近输入区，以便提交前确认。

### 6.3 需求详情

**功能要求**：
1. 主窗口需要从左到右拆分为三块主要区域。
2. 左侧区域用于生成窗口选择，宽度占整体约 1/5。
3. 中间区域用于主要生图区和底部对话框，宽度占整体约 2/5。
4. 右侧区域用于生成图片预览，宽度占整体约 2/5。
5. 中间区域内部需要上下切分，上方为主要生图区，下方为对话框、生成参数和当前 API/模型信息。

### 6.4 验收标准

- [ ] 主界面可以同时看到左侧生成窗口、中间工作区和右侧预览区。
- [ ] 左侧、中间、右侧区域默认比例符合 1:2:2。
- [ ] 中间区域上方显示生图区，下方显示对话框。
- [ ] 对话框区域能显示当前 API 和模型信息。
- [ ] 对话框区域能显示当前模式、尺寸比例、分辨率和质量。

## 非功能需求

### 兼容性要求

- v0.1.0 目标平台为 Windows 10。
- 程序交付形态为 EXE 文件。
- 主窗口在常见桌面分辨率下应保持基本可用，不应出现主要区域不可见。

### 可用性要求

- 主界面启动后应直接进入可操作状态。
- API 配置缺失、请求中、请求失败和生成完成都应有明确状态反馈。
- 关键操作入口应易于发现，包括 API 设置、模式选择、尺寸设置、质量设置、提示词输入和生成提交。

### 安全要求

- API 认证信息不应在主界面完整明文展示。
- 用户发起生图前，应能确认当前使用的 API 和模型。
- 程序不应在用户未提交请求时主动发送提示词内容。

### 稳定性要求

- API 请求失败不应导致程序崩溃。
- 生成图片加载失败时，应展示失败状态而不是破损界面。
- 当网络不可用或第三方服务异常时，应向用户提示问题原因或下一步处理方向。

## 约束与依赖

- 本版本依赖用户提供可用的第三方生图 API 信息。
- 本版本依赖本机具备访问第三方 API 的网络条件。
- 不同第三方 API 的能力、模型名称、参数支持范围和返回结果格式可能存在差异，具体适配范围需要在后续技术文档中明确。
- v0.1.0 仅承诺 Windows 10 平台，不覆盖 macOS、Linux 或移动端。
- 图片保存、批量生成、提示词模板、历史会话持久化等能力暂不纳入本版本核心范围，后续可作为独立需求扩展。
- API 服务商未明确说明能力边界时，v0.1.0 不要求程序自动推断完整能力矩阵；程序需要通过配置状态、未知状态和请求失败反馈降低用户误解。
