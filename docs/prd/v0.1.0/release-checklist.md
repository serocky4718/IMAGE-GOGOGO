# v0.1.0 发布前手动回归清单

> 这份清单给非开发背景同学也能直接照着操作。目标不是“测试所有东西”，而是确认最关键的用户路径在发布前仍然可用。

## 一、启动与基础界面

- [ ] 双击 EXE 或运行开发环境后，应用可以正常打开。
- [ ] 主界面直接进入工作台，没有空白页或报错弹窗。
- [ ] 窗口最小化、最大化、关闭按钮可正常使用。
- [ ] 左中右三栏布局正常，没有明显错位或遮挡。

## 二、API 设置

- [ ] 可以打开“API 设置”弹窗。
- [ ] 可以新增一个 API 配置。
- [ ] 输入非法 API 地址时，界面会提示 URL 格式错误。
- [ ] 输入合法 API 地址、模型和 Key 后，可以成功保存。
- [ ] 关闭应用再重新打开后，已保存的 API 配置仍然存在。

## 三、真实生成链路

### 文生图

- [ ] 输入提示词后可以成功生成图片。
- [ ] 生成完成后，中间主生图区显示结果。
- [ ] 右侧预览区出现对应缩略图和记录。

### 图生图

- [ ] 可以选择参考图片。
- [ ] 参考图片缩略图会出现在输入区。
- [ ] 输入提示词后可以成功生成图片。

## 四、图片预览与记录

- [ ] 点击右侧缩略图后，中间主生图区能切换到对应图片。
- [ ] 点击预览后可以打开大图弹窗。
- [ ] 预览弹窗能区分“生成图”与“参考图”。
- [ ] 生成记录中能看到状态、时间、模型、比例、分辨率和 quality。

## 五、能力边界提示

### unsupported

- [ ] 在 API 设置中把某项能力设为“不支持”后，回到主界面会看到明确提示文案。
- [ ] 首版不会因为 `unsupported` 自动禁用或阻断，但用户能理解这代表该能力可能不被当前 API 支持。

### unknown

- [ ] 在 API 设置中把某项能力设为“未知”后，仍然允许尝试生成。
- [ ] 界面会出现“未确认，可以尝试”的提示，而不是误导成“已支持”。

## 六、异常场景

- [ ] 把 API 指向无响应地址时，界面会显示“请求超时，请检查第三方 API 是否可用或稍后重试。”
- [ ] 生成失败后，界面不会卡死，仍然可以继续修改参数或重试。
- [ ] 如果本地状态读取或保存失败，界面会显示错误提示，而不是静默丢失。

## 七、建议记录方式

每完成一项，可以简单记录三种结果：

- `通过`
- `失败`
- `需确认`

如果失败，额外记一句：

- 你点了什么
- 实际看到了什么
- 你本来期待看到什么

这样后续继续修复会快很多。
